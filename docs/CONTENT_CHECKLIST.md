# K-SORT 콘텐츠·에셋 체크리스트

박재웅과 김현민이 16종 도감의 원문, 번역, 공식 출처, 과정 이미지를 같은 기준으로 넘겨주기 위한 표다.

## 상태 기호

- `○`: 완료 및 검수
- `△`: 들어가 있으나 검수를 못 받음
- `×`: 아직 시작하지 않음

**2026-08-07 갱신 — 콘텐츠는 모두 채워졌다.** 처음 이 표를 만들 때는 개발 착수 전이라
전부 `×`였다. 지금은 도감 16종의 한국어 문안과 네 언어 번역, 공식 출처, 품목 이미지가
모두 앱에 들어가 있고 검수 대기 문안(`__TODO__`)은 0개다.

번역 세 언어를 `△`로 둔 이유는 하나다. **문안은 다 있지만 원어민 검토를 받지 못했다.**
한국어는 기후에너지환경부 「재활용품 분리배출 가이드라인」 PDF 원문과 생활폐기물
분리배출 누리집 품목사전을 대조해 채웠다.

**"과정 이미지" 칸은 품목당 대표 이미지 한 장을 뜻한다.** 원래 계획은 단계별 3~4장
(16종 × 4 = 64장)이었으나 24시간 안에 만들 수 없어 한 장으로 줄였다.

## 품목별 전달 묶음

한 품목을 앱에 전달할 때 다음 파일과 정보가 모두 있어야 한다.

```text
itemId
├─ 검수된 한국어 요약·단계·흔한 실수·이미지 대체 텍스트
├─ 공식 출처 ID와 실제 URL
├─ needsLocalCheck와 이유
├─ 영어·중국어·베트남어 검수본
└─ public/images/items/<itemId>.webp   # 대표 이미지 한 장
```

**이미지는 품목당 한 장이다.** 원래 계획은 단계별 3~4장이었으나, 이미지가 없어도
처리 순서와 흔한 실수가 온전히 읽히도록 화면을 만들어 두어 16장으로 줄였다.
이 한 장이 도감과 스캔 화면의 선택 목록에 함께 쓰인다.

이미지에는 글자를 넣지 않는다. 네 언어 설명과 대체 텍스트는 `shared/catalog.ts`에서 관리한다.

요청 내용과 전달 형식은 [콘텐츠 요청서](CONTENT_REQUEST.md)에 정리했다.

## UI 문자열

도감 16종·FAQ 20개와 **별개로** 화면 자체의 문자열도 네 언어가 필요하다. 메뉴 이름, 버튼,
안내 문구, 오류 메시지, 게임 UI 등을 합쳐 60~100개로 추정한다.

전부 `src/i18n/strings.ts` 한 파일에 모여 있으므로 이 파일만 열면 된다. 한국어가 이미
채워진 항목에 나머지 세 언어를 더하는 방식이고, 아직 안 채운 자리는
`__TODO__:ui.nav.learn.en` 형태로 표시되어 있어 눈으로 찾을 수 있다.

```powershell
git grep -n "__TODO__" -- src/i18n
```

## 스캔 화면의 두 경로

스캔 화면은 두 가지로 쓰인다.

1. **진짜 스캔** — 이게 뭔지 모를 때 사진을 찍어 올리면 AI가 판별한다
2. **골라서 들어가기** — 품목은 아는데 사진 찍기가 번거로울 때 등록된 16종에서 고른다

2번에 쓰는 이미지는 **도감 대표 이미지를 그대로 재사용**한다. 별도 샘플 사진을
만들지 않는다.

발표 시연은 2번 경로를 쓰면 사진 준비 없이도 안정적으로 돌아간다. 1번을 라이브로
보여 줄 경우에만 직접 촬영한 사진이 필요하며, 개인정보와 브랜드 로고가 없어야 한다.
