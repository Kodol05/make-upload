# 이 프로젝트의 강점 — 사진과 대화가 이어진다

작성 2026-08-07 · 김현민

## 한 줄로

**사진으로 찾기와 챗봇이 따로 있는 게 아니라, 한쪽이 막히면 다른 쪽으로 넘어간다.**
어느 화면에서도 "여기까지"로 끝나지 않는다.

## 왜 이게 강점인가

분리배출 안내는 이미 많다. 대부분은 **목록**이다. 품목을 찾아 읽고 끝난다. 목록에 없으면
거기서 끝이고, 사진을 찍어 봐도 "모르겠다"로 끝난다.

유학생이 실제로 막히는 자리가 바로 거기다. 손에 든 물건의 **이름을 몰라서** 검색을 못 하고,
검색해도 안 나오면 물어볼 곳이 없다. 한국어로 된 안내는 읽기 어렵고, 번역해도 "종량제 봉투"
같은 말이 무엇인지 모른다.

우리가 가진 것은 둘이다.

- **사진** — 이름을 몰라도 된다. 찍으면 물건을 찾아 준다
- **대화** — 목록에 없어도 된다. 물어보면 답한다

이 둘을 **서로의 출구로 연결한 것**이 이 프로젝트의 핵심이다. 하나씩 있는 것과 이어져 있는
것은 다르다.

## 실제로 어떻게 이어지는가

```
        사진으로 찾기 ──알아봄──→ 도감 상세 ──더 궁금하면──→ 챗봇
              │                      ↑                      ↑
        도감에 없음 ─────────────────┼──────────────────────┘
                                     │
        도감 검색 ──0건────────────────┘  (찾던 말을 들고 챗봇으로)
              │
        게임에서 틀림 ────────────────┘  (그 품목 도감으로)
```

네 갈래 모두 막다른 길이 없다.

| 어디서 막히나 | 어디로 넘기나 | 무엇을 들고 가나 | 근거 |
|---|---|---|---|
| 사진에서 알아봤는데 16종에 없음 | 챗봇 | 모델이 사진에서 읽은 이름 | `PhotoFinder.tsx` |
| 도감 상세를 다 읽었는데 더 궁금함 | 챗봇 | 그 품목 ID (`contextItemId`) | `CatalogDialog.tsx` |
| 검색했는데 0건 | 챗봇 | 찾던 말 | `CatalogSection.tsx` |
| 게임에서 틀림 | 그 품목 도감 상세 | 주소에 담아 (`#/catalog?item=…`) | `GamePage.tsx` |

넷 다 통로 하나(`src/features/chat/askChat.tsx`)를 쓴다. 처음 하나를 만들 때 뒤의 것들을
염두에 두고 뺐고, 두 번째부터는 화면 쪽 열 줄 남짓이 전부였다.

## 이어 붙이면서 지킨 것

길을 넓히면 헛소리도 같이 넓어진다. 그래서 **어디까지가 확인된 것인지**를 앱이 스스로 구분한다.

**챗봇은 근거를 세 등급으로 나눈다.**

| 등급 | 언제 | 출처 |
|---|---|---|
| `answered` | 검수된 도감이 다루는 것 | 붙인다 |
| `needs_local_check` | 도감 밖이지만 분리배출 이야기 | **안 붙인다.** 도감에 없다는 사실을 답변 안에 적는다 |
| `out_of_scope` | 쓰레기와 무관 | 답하지 않는다 |

**지어낸 것은 화면까지 못 온다.**

- 모델이 등록 안 된 출처 ID를 붙여 와도 서버가 걸러 낸다 (`keepKnownIds`)
- 사진에서 모델이 없는 품목 ID를 지어내도 `unknown`으로 바꾼다 (`sanitiseObjects`)
- 검수가 끝나지 않은 문안은 모델에게 아예 주지 않는다. 안 그러면 자리 표시를 사실처럼 인용한다
- 출처 URL은 실제로 열어 확인한 것만 링크가 된다. 미확인은 빈 문자열로 두고 UI가 링크를 안 만든다

**모호하면 확정하지 않는다.** 사진 결과에 `high / medium / low` 확실성을 두고, 확신이 없으면
정답으로 밀지 않고 사용자가 고르게 한다.

**남기지 않는다.** 사용자 사진과 대화 원문은 서버에도 로그에도 저장하지 않는다. 무료 등급에서는
제출 이미지가 학습에 쓰일 수 있어, 사진을 올리기 **전에** 그 사실을 알린다.

## 시연에서 보여 줄 순서

이 강점은 화면 하나로는 안 보인다. **넘어가는 것**을 보여 줘야 한다.

1. **사진을 찍는다** — 여러 물건이 한 번에 잡히고 네모가 그려진다
2. **그중 도감에 있는 것**을 눌러 상세로 간다. 처리 순서와 공식 출처가 나온다
3. 상세 아래 **"이 품목에 대해 챗봇에게 물어보기"** — 챗봇이 그 품목을 아는 채로 열린다
4. 이번엔 **도감에 없는 것**을 찍는다. "판단하지 못했습니다"가 뜨지만 **"AI에게 물어보기"**가
   함께 있다. 누르면 AI가 사진에서 읽은 이름이 질문 자리에 들어와 있다
5. 챗봇이 답한다. 출처는 안 붙고 "도감에 없으니 지자체 확인이 필요하다"가 답변 안에 있다

여기까지가 하나의 이야기다. **AI가 못 맞혀도 사용자는 답을 얻는다.**

발표 중 API가 막힐 때를 대비해 추천 질문 스무 개는 모델 없이 답한다. 챗봇 창을 열어 추천
질문만 눌러도 대화가 이어진다.

## 아직 아닌 것

정직하게 적어 둔다. 보고서의 한계 항목에 그대로 쓸 수 있다.

- 도감이 다루는 것은 **16종**이다. 자주 헷갈리는 것을 고른 것이지 한국의 쓰레기 전부가 아니다.
  그 밖은 챗봇이 받되 출처 없이 답한다
- 분리배출 규칙은 **자치구마다 다르다.** 우리는 자치구 데이터가 없어서 "지자체 확인"으로
  넘긴다. 지어내지 않는 쪽을 골랐다
- 네 언어 번역을 **실제 유학생에게 검토받지 못했다**
