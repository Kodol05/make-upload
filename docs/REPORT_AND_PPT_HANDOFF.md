# K-SORT 보고서·PPT 작성 인수인계

박재웅이 다른 컴퓨터에서 보고서와 5분 발표 자료를 바로 이어서 만들기 위한 문서다. 개발 진행에 따라 이 파일의 검증표와 증거 파일명을 갱신한다.

## 1. 프로젝트 기본 정보

- 프로젝트명: K-SORT
- 팀명: 메이크 업로드 (Make Upload)
- 소속: 명지전문대 AI게임소프트웨어과
- 팀원:
  - 박재웅: 팀장, 기획, 발표, AI 영상 제작
  - 김현민: 웹앱 개발, AI 에셋 제작, 게임
- 대상 사용자: 한국 생활과 분리배출 제도가 낯선 명지전문대 유학생
- 공익 목적: 올바른 분리배출 행동을 교육해 재활용 오염과 잘못된 폐기 가능성을 줄이는 것
- 핵심 문장: `Learn it. Scan it. Sort it right in Korea.`

## 2. 문제 정의

보고서와 발표에서는 다음 흐름으로 문제를 설명한다.

1. 한국의 분리배출은 재질뿐 아니라 오염 상태, 부착물, 지역별 규칙에 따라 방법이 달라질 수 있다.
2. 한국어가 익숙하지 않은 유학생은 안내 문구를 이해하기 어렵고, 손에 든 물건을 어떤 분류로 버릴지 즉시 판단하기 어렵다.
3. 텍스트 안내만으로는 라벨 제거, 세척, 분리 같은 실제 행동 순서를 전달하기 어렵다.
4. K-SORT는 네 언어, 과정 이미지, 사진 인식, 근거 기반 질문, 게임 복습을 하나의 학습 여정으로 연결한다.

검증되지 않은 유학생 통계, 재활용률, 탄소 절감량은 사용하지 않는다. 수치를 넣으려면 공식 출처와 기준 연도를 함께 기록한다.

## 3. 솔루션 설명 순서

```text
2분 영상으로 4대 원칙 학습
→ AI Sort Scan으로 사진 속 쓰레기 탐지
→ 16종 과정형 도감에서 실제 처리 순서 확인
→ 네 언어 AI 챗봇으로 추가 질문
→ 게임으로 복습
```

차별점은 AI 기능의 개수가 아니라 각 기능이 다음 행동으로 연결된다는 점이다. 스캔 결과는 자유로운 AI 설명에서 끝나지 않고 팀이 검수한 도감으로 이동한다. 챗봇은 임의의 웹 정보를 생성하지 않고 등록된 출처 ID를 앱이 공식 URL로 연결한다.

## 6. 보고서에서 강조할 설계 판단

> 이 가운데 가장 앞세울 것은 **사진과 대화가 서로의 출구로 이어진다**는 점이다.
> 근거와 시연 순서는 [CORE_STRENGTH](CORE_STRENGTH.md)에 따로 정리했다.

- 사진에서 알아봤지만 도감에 없으면 챗봇으로, 검색이 0건이면 챗봇으로, 게임에서 틀리면
  그 품목 도감으로 넘긴다. 어느 화면에서도 막다른 길이 없다.
- API 키를 브라우저에 넣지 않고 서버(Vercel Functions) 환경 변수로 보호했다.
  처음에는 Cloudflare Worker였으나 Gemini가 그 출구 IP를 지역 차단해 옮겼다.
- 전역 언어 상태 하나로 영상 자막, 화면 문구, 도감, AI 결과, 게임 UI를 함께 바꾼다.
- AI가 출처 URL을 생성하지 않고 앱이 검수된 source ID를 실제 URL에 연결한다.
- 챗봇이 근거를 세 등급으로 나눈다. 도감이 다루면 출처를 붙이고, 도감 밖이면 출처 없이
  답하며 그 사실을 답변에 적고, 쓰레기와 무관하면 답하지 않는다.
- 사진 결과에 `high / medium / low` 확실성 단계를 두고 모호한 결과를 사용자가 확인한다.
- AI가 실패해도 수동 도감, 영상 요약, 게임이 독립적으로 동작한다. 챗봇의 추천 질문 20개는
  모델을 부르지 않고 답하므로 API가 막혀도 대화가 이어진다.
- 사용자 사진과 대화 원문을 K-SORT 서버에 저장하지 않는다.

## 9. 7장 PPT 구조

### 1장 — K-SORT

- 팀 메이크 업로드
- `Learn it. Scan it. Sort it right in Korea.`
- Made for international students at Myongji College
- 발표: 박재웅 / 개발·AI 에셋: 김현민

### 2장 — 쓰레기통 앞에서 멈추는 유학생

- 언어 장벽
- 품목과 오염 상태에 따른 복잡한 분류
- 텍스트만으로 이해하기 어려운 행동 순서
- 환경 보호와 캠퍼스 생활에 동시에 연결된 문제

### 3장 — 하나의 학습 여정

- 배우기
- AI로 스캔하기
- 과정형 도감 확인
- AI에게 질문
- 게임으로 복습

사용자 여정 화살표와 실제 화면 3장을 사용한다.

### 4장 — AI Sort Scan 라이브 데모

- 사진 한 장에서 최대 5개 물체 탐지
- 도감 16종으로 제한된 매핑 — **못 이으면 챗봇으로 넘긴다**
- 모호하면 사용자 확인
- 사진 저장 없음

이 슬라이드에서 발표 화면을 웹앱으로 전환한다. 시연 순서는
[CORE_STRENGTH](CORE_STRENGTH.md)의 "시연에서 보여 줄 순서"를 따른다.

### 5장 — 네 언어로 행동까지 안내

- 한국어·영어·중국어·베트남어
- 영상 자막, UI, 도감, 챗봇, 게임 동시 전환
- 품목별 3~4개 과정 이미지
- 검수된 공식 자료 링크

### 6장 — AI와 사람이 함께 만든 24시간 파이프라인

- Seedance → Typecast → Suno → GPT Image → Gemini → AI 코딩
- 박재웅: 기획·콘텐츠·영상·발표
- 김현민: 웹앱·AI 에셋·게임
- AI 출력은 사람이 사실·시각·코드 테스트로 검수

### 7장 — 작은 습관을 실제 행동으로

- 유학생의 한국 생활 적응 지원
- 올바른 분리배출이라는 공익 가치
- 지역별 공식 정보와 교내 시스템으로 확장 가능
- QR 코드 또는 배포 URL

## 10. 5분 발표 대본 시간표

| 구간 | 시간 | 누적 |
| --- | ---: | ---: |
| 문제와 유학생 관점 | 35초 | 0:35 |
| 영상 하이라이트와 4대 원칙 | 40초 | 1:15 |
| AI Sort Scan·도감·언어 전환 | 70초 | 2:25 |
| 다국어 챗봇 | 35초 | 3:00 |
| 게임 | 30초 | 3:30 |
| AI 제작 파이프라인 | 40초 | 4:10 |
| 공익성·확장성·팀 소개 | 30초 | 4:40 |
| 화면 전환·예비 시간 | 20초 | 5:00 |

2분 영상 전체는 재생하지 않고 약 30초 하이라이트만 사용한다. 라이브 시연은 고정 샘플 사진과 사전 검증한 질문을 사용한다.

## 11. 발표용 고정 시연 시나리오

1. 한국어 홈에서 제품 여정을 한 문장으로 소개한다.
2. 영어 또는 베트남어로 언어를 바꾼다.
3. 투명 페트병과 캔이 함께 있는 샘플 사진을 AI Sort Scan에 넣는다.
4. 페트병 박스를 선택해 라벨 제거를 포함한 과정형 도감을 연다.
5. 같은 언어로 `컵라면 용기가 깨끗하지 않으면 어떻게 버려요?`에 해당하는 질문을 챗봇에 입력한다.
6. 답변 아래 공식 출처와 지역 확인 안내를 보여준다.
7. 게임을 짧게 플레이하고 점수·복습 링크를 보여준다.
8. 슬라이드로 돌아가 AI 제작 파이프라인과 역할을 설명한다.

발표 직전 라이브 API가 불안정하면 `예시 결과 보기`를 사용한다고 명확히 말하고, 실제 AI인 것처럼 위장하지 않는다.

## 12. 한계와 향후 개선

현재 한계:

- 카메라 기반 판단은 오인식할 수 있어 사용자 확인이 필요하다.
- 한국의 세부 배출 규칙은 지역마다 다를 수 있다.
- 16개 품목은 일상 쓰레기 전체를 포함하지 않는다.
- 번역은 AI 초안 이후 사람 검수가 필요하다.
- 해커톤 MVP는 사용자 계정과 장기 학습 기록을 저장하지 않는다.

향후 개선:

- 명지전문대 교내 수거함 위치와 시설별 규칙 연동
- 실제 유학생 사용자 테스트와 쉬운 표현 개선
- 지원 품목과 FAQ 확대
- 게임 오답을 활용한 맞춤 복습
- 지자체 공식 데이터 연동과 최신성 표시

## 13. 다른 컴퓨터에서 보고서 작업 시작 프롬프트

복제한 저장소에서 `docs/AI_PROCESS_AND_PROMPTS.md`의 `보고서 작성 프롬프트` 또는 `PPT 작성 프롬프트`를 사용한다. AI에게 문서 전체를 읽게 한 뒤 `git log --oneline`과 실제 증거 파일을 함께 제공한다.

완료된 기능과 계획 중인 기능을 반드시 구분하고, 이 문서의 검증표가 `미실행`인 항목을 성공 사례로 서술하지 않는다.
