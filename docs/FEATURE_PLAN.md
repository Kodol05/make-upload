# 추가 기능 — 계획과 결과

작성 2026-08-07 · 김현민

## 이 문서의 쓰임

지금부터 붙일 기능 다섯 개를 적어 둔다. **하나를 끝낼 때마다 "결과"에 무엇이 실제로
달라졌는지 채운다.** 계획만 남은 문서는 보고서에 쓸 수 없고, 다 끝난 뒤에 기억으로 쓰면
왜 그렇게 정했는지가 빠진다.

앞의 넷은 성격이 같다. **이미 만들어 둔 것들이 서로 이어지지 않아서 생긴 막다른 길을
막는 일**이다. 지금 이 앱은 소개 → 영상 → 도감 → 게임으로 한 방향으로만 흐르고, 되돌아오는
길이 없다.

| | 기능 | 성격 | 상태 |
|---|---|---|---|
| 1 | 도감 상세 → 챗봇 | 만들어 놓고 안 쓰던 것을 잇는다 | **완료** |
| 2 | 게임 결과 → 도감 | 막다른 길을 막는다 | 대기 |
| 3 | 추천 질문을 API 없이 | 시연 안전성 | 대기 |
| 4 | 검색 0건 → 챗봇 | 막다른 길을 막는다 | 대기 |
| 5 | 화면 전환 | 인상 | 대기 |

---

## 1. 도감 상세에서 챗봇으로 바로 묻기

### 무엇을

도감 상세에 "이 품목에 대해 물어보기"를 붙인다. 누르면 챗봇이 열리고, 지금 보던 품목이
무엇인지 아는 상태로 대화가 시작된다.

### 왜

**이미 절반이 만들어져 있는데 화면에서 안 쓰고 있다.** `contextItemId`가 요청 스키마
(`shared/schemas.ts`)에도, 서버 처리(`worker/src/chat.ts`)에도, 시스템 프롬프트에도 들어가
있다. 그런데 그 값을 보내는 화면이 한 군데도 없다.

붙이는 비용이 거의 없는데 얻는 게 크다. 도감은 "정해진 16종의 정해진 답"이고 챗봇은 "그 밖의
것도 답한다"인데, 지금은 둘 사이를 사용자가 직접 건너가야 한다.

### 확인 방법

- 도감 상세에서 단추를 누르면 챗봇이 열린다
- 서버로 가는 요청에 그 품목의 `contextItemId`가 실려 있다
- 상세를 닫아도 대화는 남는다 (챗봇은 라우트 바깥에 있다)

### 결과

도감 상세의 흔한 실수 아래에 "이 품목에 대해 물어보기"를 붙였다. 누르면 상세가 닫히고
챗봇이 열리며, 입력란에 품목 이름이 들어와 있다. 바로 보내도 되고 이어서 써도 된다.

**보내지 않고 넣어만 둔다.** 무엇이 물어질지 보고 나서 고칠 수 있어야 한다고 봤다.

만들면서 정한 것 셋.

- **통로를 따로 뒀다.** 챗봇은 페이지를 옮겨도 대화가 남도록 라우트 바깥에 있고, 부르는
  쪽은 라우트 안쪽 깊은 곳에 있다. 사이의 컴포넌트마다 콜백을 물려 내리는 대신
  `askChat.tsx`에 통로를 하나 뒀다. 4번(검색 0건)도 같은 통로를 쓴다
- **상세를 먼저 닫는다.** 상세가 포커스를 가두고 있어서, 열어 둔 채로 챗봇을 띄우면
  키보드가 챗봇에 닿지 못한다
- **효과가 아니라 렌더 중에 맞춘다.** 효과로 열면 닫힌 화면이 한 번 그려진 뒤에 열려서
  깜빡인다. 입력란도 마찬가지다. lint(`react-hooks/set-state-in-effect`)가 먼저 잡아 줬다

단추는 채우지 않고 테두리만 둘렀다. 처리 순서와 흔한 실수보다 먼저 눈에 띄면 안 된다.
글자 대비 7.78:1, 마우스를 올렸을 때 6.81:1.

테스트 셋을 새로 뒀다. 품목이 실제로 요청까지 실려 가는지, 스스로 열었을 때는 안 실리는지,
도감에서 챗봇까지 실제로 이어지는지(통합).

## 2. 게임 결과에서 틀린 품목을 도감으로

### 무엇을

게임이 끝나면 틀린 품목이 목록으로 나온다. 그걸 누르면 해당 도감 상세가 열리게 한다.

### 왜

지금은 **"이건 틀렸습니다"에서 끝나고 배우러 갈 길이 없다.** 틀린 것을 알려 주는 이유는
다시 안 틀리게 하려는 것인데, 정작 다시 볼 곳으로 데려다주지 않는다.

목록을 만드는 코드(`result.learnedItemIds`)는 이미 있고 이름과 분류까지 보여 준다. 누를 수
있게만 만들면 된다.

보고서 관점에서도 이게 있어야 "네 화면이 서로 이어진 하나의 학습 여정"이라고 말할 수 있다.
지금은 한 방향으로만 흐른다.

### 확인 방법

- 결과 화면의 틀린 품목을 누르면 그 품목의 도감 상세가 열린다
- 키보드로도 닿는다 (지금은 그냥 목록이라 초점이 안 간다)

## 3. 추천 질문을 API 없이 답하기

### 무엇을

추천 질문 셋은 우리가 고른 FAQ 그대로다. 답도 이미 검수해서 갖고 있으므로 모델을 부르지 않고
바로 답한다. 하나를 쓰면 그 자리에 다음 질문이 들어오고, 스무 개를 다 돌면 처음으로 되돌아온다.

### 왜

세 가지가 한꺼번에 좋아진다.

- **시연이 안전해진다.** 발표 중에 무료 한도가 걸리거나 망이 끊겨도 챗봇이 답을 한다. 지금은
  추천 질문조차 모델에 기대고 있어서 API가 죽으면 챗봇이 통째로 무용지물이 된다
- **기다림이 없다.** 정해진 답을 받는 데 몇 초를 기다릴 이유가 없다
- **한도를 아낀다.** 무료 등급이라 하루 호출 수가 빡빡하다

`answered` 상태와 출처까지 FAQ가 이미 들고 있어서(`relatedItemIds`, `sourceIds`) 화면 쪽은
바꿀 게 없다.

### 확인 방법

- 추천 질문을 눌렀을 때 네트워크 요청이 나가지 않는다
- 답과 출처가 도감 상세와 같은 모양으로 나온다
- 하나를 쓰면 그 자리만 바뀌고 나머지 둘은 그대로 남는다
- 스무 개를 다 쓰면 처음 질문으로 돌아온다

## 4. 검색 결과가 없을 때 챗봇으로 넘기기

### 무엇을

도감 검색이 0건이면 "없습니다" 안내 대신, 검색어를 그대로 들고 챗봇을 여는 길을 준다.

### 왜

지금은 **막다른 길이다.** 16종에 없는 물건을 찾으면 안내문만 뜨고 끝난다. 그런데 챗봇은
도감 밖도 답하도록 이미 바꿔 뒀다 — 도감에 없다는 사실과 지자체 확인이 필요하다는 것을
답변에 적고, 출처는 붙이지 않는 방식이다.

즉 답할 수 있는 곳이 있는데 안내를 안 하고 있다. 16종은 자주 헷갈리는 것을 고른 것이지
한국의 쓰레기 전부가 아니다.

### 확인 방법

- 도감에 없는 말을 검색하면 챗봇으로 가는 길이 보인다
- 눌렀을 때 검색어가 그대로 질문 자리에 들어가 있다

## 5. 화면이 넘어갈 때 자연스럽게

### 무엇을

네 화면 사이를 옮길 때 내용이 툭 바뀌지 않고 자연스럽게 이어지게 한다.

### 왜

이 앱은 네 화면이 한 줄로 이어진 "여정"이라고 말하고 있는데, 정작 넘어갈 때는 화면이 순간
교체된다. 걸어간다기보다 순간이동에 가깝다.

### 지켜야 할 것

앞서 CSS를 무너뜨린 적이 있어서 조건을 먼저 적어 둔다.

- **움직임을 줄여 달라는 설정이면 전환도 없앤다.** 전정 장애가 있는 사람에게 화면이 미끄러지는
  것은 그 자체가 문제다. `usePrefersReducedMotion`이 이미 있다
- **내용이 늦게 뜨면 안 된다.** 전환은 짧게(0.2초 안팎) 두고, 기다리게 만들지 않는다
- **초점 이동을 깨지 않는다.** 지금 페이지를 옮기면 본문으로 초점을 보낸다. 키보드와 스크린
  리더 사용자가 이동한 것을 아는 유일한 단서라, 전환 때문에 이게 어긋나면 안 된다
- **기존 CSS 파일을 건드리지 않는다.** 소개를 `intro.css`로 뗀 것과 같은 방식으로, 전환만
  따로 두고 이름이 겹치지 않게 한다

### 확인 방법

- 네 화면을 오갈 때 내용이 이어지는 느낌이 든다
- 움직임 줄이기 설정을 켜면 전환이 사라진다
- 페이지를 옮긴 뒤에도 초점이 본문에 있다 (테스트로 잠근다)

## 순서

1 → 2 → 4 → 3 → 5 로 간다.

앞의 셋(1·2·4)은 이미 있는 것을 잇는 일이라 깨질 데가 거의 없고 서로 독립적이다. 3번은
챗봇 안쪽을 바꾸는 일이라 그다음, 5번은 네 화면 전체에 걸리므로 마지막에 둔다. 하나씩
끝내고 화면으로 확인한 뒤 다음으로 넘어간다.
