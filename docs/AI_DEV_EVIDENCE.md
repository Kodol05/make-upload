# 개발 중간 점검 — AI에게 무엇을 시켰고 무엇이 나왔나

작성 2026-08-07 · 김현민 (웹앱·게임·에셋)

## 이 문서의 자리

[AI_PROCESS_AND_PROMPTS](AI_PROCESS_AND_PROMPTS.md)는 영상·음성·이미지·번역을 만들 때 쓴
프롬프트를 모아 둔 곳이고, [worklog](worklog.md)는 한 줄짜리 이력이다. 이 문서는 그 사이가
비어 있어서 쓴다. **개발하는 동안 AI를 어떻게 부렸고, 그 결과 무엇이 달라졌는가.**

앞쪽(§2~§6)은 사람이 놓쳤을 법한 것과 AI가 틀려서 되돌린 것을 사례로 적었고, 뒤쪽(§7~§8)에
기술 스택과 기능을 정리했다. 스택은 이름만 나열하지 않고 **왜 그것을 골랐는지**를 함께 적었다.
버전 하나를 잘못 고르면 lint가 통째로 깨지는 일을 실제로 겪었기 때문이다.

앞쪽이 더 중요하다고 본다. AI가 다 했다는 말보다, 어디까지 믿고 어디서 걸러 냈는지가 실제로
쓸모 있는 기록이기 때문이다.

## 2. 지시하는 방식이 결과를 갈랐다

같은 도구를 써도 무엇을 어떻게 요구하느냐에 따라 나오는 것이 달랐다. 되풀이해서 효과가 있던
방식 넷을 적는다.

### 2.1 "고쳐 줘" 대신 "왜 그런지 찾아 줘"

GitHub Pages 배포가 여섯 번 연속 실패했을 때, 처음에는 워크플로 설정을 이리저리 바꾸는 식으로
접근했다. 방향을 바꿔서 **"코드적 문제가 있는 것 같은데 그 이유를 찾아 달라"**고 시켰더니
결론이 뒤집혔다. 원인은 우리 코드가 아니라 `actions/deploy-pages`의 타임아웃 10분이 하드
상한이라는 사실이었고, 그날 GitHub 큐 대기가 3~9분이라 그 상한에 걸리고 있었다.

증상을 고치라고 시켰으면 계속 워크플로만 만졌을 것이다. 원인을 찾으라고 시키니 "우리가 고칠
수 있는 문제가 아니다"라는, 사람이 듣기 싫지만 맞는 답이 나왔다.

### 2.2 규칙은 대화가 아니라 파일에 둔다

같은 지시를 매번 되풀이하는 대신 `CLAUDE.md`에 박아 뒀다. "한 번에 기능 하나만", "확실하지
않으면 묻는다", "커밋 전에 `npm run check`", "API 키는 `.dev.vars`와 Vercel 환경 변수에만".

효과가 분명했던 건 보안 쪽이다. 세션이 바뀌어도 키가 코드나 커밋에 새지 않았고, 사용자 사진과
대화 원문을 로그에 남기지 않는 규칙도 계속 지켜졌다. 대화로만 말했으면 긴 작업 중에 흐려졌을
것이다.

### 2.3 되돌릴 수 있는 크기로 자른다

이건 실패하고 나서 배운 것이다. 소개 화면을 고치면서 2,400줄짜리 `identity.css` 안에서 규칙을
네 번 갈아 끼웠는데, 어느 것이 이기는지 눈으로 확인할 수 없게 되면서 다른 화면까지 어긋났다.
결국 통째로 되돌렸다.

두 번째 시도에서는 방식을 바꿨다. 소개만 `IntroPage.tsx` + `intro.css`로 떼어 내고 클래스를
전부 `intro-`로 시작하게 해서, 기존 규칙과 한 글자도 겹치지 않게 만들었다. 그러고 나서
**영상만 → 글자와 덮개 → 단추** 순으로 한 단계씩 확인받으며 쌓았다. 같은 화면을 같은 사람이
같은 도구로 다시 만들었는데 이번에는 아무것도 깨지지 않았다.

### 2.4 감이 아니라 숫자를 요구한다

"글자가 잘 보이나?"는 사람마다 다르게 답한다. 그래서 색을 정할 때마다 실제 픽셀을 뽑아
대비를 계산하게 시켰다. 그림 위에 글자를 얹을 때는 그림에서 가장 어두운 픽셀을 골라 덮개까지
합성한 뒤 재고, 영상 위라면 프레임을 24장 뽑아 그중 최악을 골랐다.

이 습관이 실제로 사고를 막은 사례가 §3.5에 있다.

## 3. AI가 먼저 잡아낸 것

사람이 그냥 지나쳤거나, 나중에 시연 중에야 알았을 것들이다.

### 3.1 통과하는데 아무것도 검사하지 않던 테스트

자막이 언어에 따라 바뀌는지 확인하는 테스트가 초록불이었다. 그런데 안을 들여다보니 jsdom이
`HTMLTrackElement.track`을 만들지 않아서, `if (track.track)` 안쪽이 **한 번도 실행되지 않은 채**
통과하고 있었다.

거짓 안심을 주는 테스트는 없는 것보다 나쁘다. 해당 로직을 `showSubtitles`로 떼어 내 가짜
track으로 직접 검사하게 바꿨다.

### 3.2 자막이 안 뜨는데 오류도 안 남던 문제

언어를 바꾸면 자막 파일은 제대로 갈아 끼워지는데 화면에는 안 나왔다. `<track default>`는
재생기가 처음 뜰 때 한 번만 먹고, 이후에 붙는 track은 꺼진 채로 들어온다.

이건 실패해도 콘솔에 아무것도 안 남는 종류다. 게다가 이 무렵 재웅이 영상에 박혀 있던 자막을
빼면서, **자막이 안 뜨면 아무 자막도 없는 상태**가 됐다. 시연 중에 알았으면 손쓸 방법이 없었다.

### 3.3 번역이 채워지자 드러난 검색 회귀

도감 검색은 한동안 잘 되고 있었다. 번역을 전부 채우고 나니 베트남어에서 '캔'을 검색하면 결과가
0건이 됐다.

원인은 새 버그가 아니라 **원래 있던 버그가 가려져 있던 것**이었다. 번역이 비어 있을 때 한국어로
떨어지는 폴백에 검색이 우연히 기대고 있었고, 번역이 채워지자 그 우연이 사라졌다. 검색어를 고른
언어 + 한국어를 항상 함께 보도록 고쳤다.

### 3.4 배포본에서만 깨질 뻔한 것

이 앱은 `/make-upload/` 아래에 올라가서 자산 경로에 base가 붙어야 한다. 그런데 **Vite는 CSS의
`url()`에는 base를 붙이지 않는다.** 로컬에서는 멀쩡하고 배포본에서만 404가 난다.

빌드 산출물을 직접 열어 확인한 뒤, 경로를 아는 React 쪽에서 CSS 변수로 넘기는 방식으로 바꿨다.

### 3.5 대비 1.00:1

소개 화면에서 분류 표시와 이름을 두 배로 키워 달라는 요청이 있었다. 크기만 바꾸면 되는 일처럼
보였는데, 재 보니 표시가 앉는 자리의 대비가 **1.00:1**이었다. 글자와 배경의 밝기가 같아서 사실상
안 보인다는 뜻이다.

원인은 대비를 "자리"에 기대고 있었기 때문이다. 칸 아래쪽만 흰색으로 덮어 두고 글자를 그 안에
앉혔는데, 표시가 커지면서 덮개가 닿지 않는 위쪽까지 올라왔다. 크기만 늘렸으면 화면에서는
"그림이 좀 흐릿하네" 정도로 보이고 넘어갔을 것이다.

## 4. AI가 틀렸고 사람이 되돌린 것

여기가 이 문서에서 제일 값어치 있는 부분이라고 본다.

### 4.1 주소를 지어냈다

출처 중에 한글 도메인(`분리배출.kr`)이 있어서 퓨니코드 변환이 필요했다. AI가 내놓은 값은
그럴듯했지만 틀린 것이었다. 실제로 계산해 보고서야 맞는 값이 나왔다.

이 일 이후로 출처 URL은 **전부 직접 열어 응답을 확인**하고, 확인 안 된 것은 빈 문자열로 두어
화면이 링크를 만들지 않게 했다. 지어낸 주소가 "공식 출처"로 붙는 것이 이 앱에서 가장 나쁜 종류의
오류다.

### 4.2 멀쩡한 파일을 고칠 뻔했다

자막 파일을 검사하는 정규식을 만들면서 시각을 `HH:MM:SS`로 강제했다. 그런데 WebVTT는 시(hour)를
생략할 수 있어 `00:00.000`도 옳은 표기다. 그 결과 **멀쩡한 영어·중국어·베트남어 자막 셋이
"비어 있다"고 잘못 읽혔다.**

검사 도구가 틀렸는데 데이터를 고치러 갈 뻔했다. 규격을 다시 읽고 정규식을 고쳤다.

### 4.3 그림을 망칠 뻔했다

도감 카드의 그림 배경을 회색으로 통일하려고 테두리에서 색을 번지게 하는 방식을 썼다. 실행해
보니 16장 중 대부분이 **3~12%만 칠해졌다.** 그림 배경이 평평하지 않고 가장자리로 갈수록 옅어지는
그라데이션이었기 때문이다.

그대로 뒀으면 얼룩진 그림 16장이 남았다. 되돌리고, 그림 대신 칸 쪽을 칠하는 방향으로 바꿨다.

### 4.4 CSS를 무너뜨렸다

§2.3에 적은 그 일이다. 소개 화면 규칙을 큰 파일 안에서 반복해 갈아 끼우다 다른 화면까지
어긋났다. 커밋 다섯 개를 되돌렸다.

되돌린 것도 커밋으로 남겼기 때문에 소개 밖에서 한 작업(메뉴 표시, 단추 크기, 게임 수거함)은
그대로 살릴 수 있었다. 실제로 되돌린 뒤 diff로 "소개 관련 파일은 바이트까지 같고 나머지는
유지됨"을 확인했다.

### 4.5 파일 형식을 억지로 바꾸려 했다

두 번째 소개 영상이 `.mov`(QuickTime 컨테이너)로 왔다. 다시 인코딩하지 않으려고 파일 앞머리의
컨테이너 표시만 바이트 단위로 바꿔 봤는데, 박스 크기가 달라지면서 내부 위치가 전부 어긋나
재생이 깨졌다. 재웅에게 MP4로 다시 받아 해결했다.

### 4.6 문체 지침을 사람이 되돌렸다

"AI가 쓴 글처럼 보이지 않게" 써 달라고 한 뒤, AI가 스스로 세운 원칙 중에 **"16개 항목을 같은
문형으로 찍어내지 않는다"**가 있었다. 이건 과했다. 도감은 같은 성격의 항목이 16개 나열되는
곳이라 어느 정도 일관성이 있어야 읽기 쉽다. "템플릿 느낌만 피하고 일관성은 유지"로 다시 잡았다.

## 5. 숫자로 정한 값

색과 투명도는 전부 실측해서 정했다. 기준은 WCAG 대비 4.5:1(본문), 3:1(큰 글자·그래픽)이다.

| 어디 | 정한 값 | 최악의 경우 대비 |
|---|---|---|
| 소개 영상 위 흰 글자 | 덮개 62% | 4.90:1 / 5.13:1 (영상 두 편) |
| 분류 상자 위 글자 | 덮개 92% | 4.59:1 |
| 게임 시작 안내 | 그림 40% · 덮개 78% | 11.79:1 |
| 화면 전체 배경 | 11% | 11.17:1 |
| 진행 막대 칸 | — | 3.01:1 |

소개 영상은 프레임 24장을 뽑아 보니 위·가운데·아래 어느 띠에서도 가장 어두운 픽셀이 L=0.000,
가장 밝은 픽셀이 L=0.95였다. **덮개 없이는 어떤 글자색도 어느 순간엔 읽히지 않는다**는 뜻이라,
덮개가 선택이 아니라 필수라는 것이 숫자로 나왔다.

## 6. 근거를 어떻게 걸렀나

분리배출은 통념이 많이 도는 주제다. 검색으로 나오는 블로그를 그대로 쓰면 틀린 내용이 앱에
박힌다.

- 기후에너지환경부 「재활용품 분리배출 가이드라인」 **PDF 원문**과 생활폐기물 분리배출 누리집
  품목사전을 대조해서 채웠다. 이 과정에서 통념 3건을 정정했다
- 출처 5개는 전부 실제로 열어 응답을 확인했다
- 검수가 끝나지 않은 문안(`__TODO__`)은 **챗봇에게 보내는 지식에서 아예 제외**한다. 안 그러면
  모델이 자리 표시를 사실처럼 인용한다. 이건 테스트로 잠가 뒀다
- 챗봇은 근거를 세 등급으로 나눈다. 도감이 다루는 것은 출처를 붙여 답하고, 도감 밖은 아는
  대로 답하되 출처를 붙이지 않고 "도감에 없다"는 사실을 답변 안에 적는다. 분리배출과 무관한
  질문은 답하지 않는다

## 7. 기술 스택

라이브러리를 고를 때 기준은 하나였다. **24시간 안에 끝내야 하니, 배우는 데 시간이 드는 것은
쓰지 않는다.** 그래서 상태 관리 라이브러리도, 라우터도, CSS 프레임워크도 넣지 않았다.

| 자리 | 쓴 것 | 왜 |
|---|---|---|
| 화면 | React 19 + Vite 8 | 빌드가 빠르고 설정이 적다 |
| 언어 | TypeScript **6.0.3 고정** | 7.x는 typescript-eslint가 아직 지원하지 않아 lint가 깨진다. 미리 확인하고 고정했다 |
| 검증 | Zod 4 | 브라우저와 서버가 같은 스키마를 나눠 쓴다. 모델 응답 검증에도 그대로 쓴다 |
| 테스트 | Vitest 4 + Testing Library | 빌드 도구와 같은 설정을 쓴다 |
| 스타일 | 일반 CSS + 토큰 파일 | 색·간격·글자 크기를 `tokens.css` 한 곳에 모았다 |
| 라우팅 | 직접 만든 해시 라우팅 | 페이지 넷뿐이라 `useHashRoute` 훅 하나로 끝난다 |
| API | **Vercel Functions** | 처음엔 Cloudflare Workers였다. §3.6 참조 |
| 모델 | `gemini-3.5-flash-lite` | 챗봇·스캔 공용. 상위 모델은 무료 한도가 하루 20회뿐이었다 |
| 배포 | GitHub Pages (`base: /make-upload/`) | 정적 호스팅. API만 Vercel에 따로 있다 |

바꿔야 했던 것 둘은 기록해 둘 만하다.

- **Cloudflare → Vercel.** Gemini가 Cloudflare 출구 IP를 지역 차단해서 API 호출이 전부
  막혔다. 코드는 그대로 두고 실행 자리만 옮겼다. `worker/` 폴더 이름은 이전 흔적으로 남아
  있고 실제 실행은 `api/[...path].ts`가 한다
- **TypeScript 6 고정.** 최신 버전을 쓰려다 lint가 통째로 깨지는 것을 먼저 확인하고 되돌렸다.
  작업 시작 전에 잡아서 시간을 안 버렸다

`npm run check` 하나가 lint · 테스트 · 빌드를 모두 돌린다. 커밋 전에 항상 이걸 통과시킨다.

## 8. 기능

네 화면이 한 줄로 이어진다. **소개 → 영상으로 배우기 → 도감 → 게임**, 그리고 어느 화면에서든
챗봇을 열 수 있다.

### 소개

영상 두 편이 화면 가로를 채우며 번갈아 돌고, 그 위에 큰 글 한 줄과 단추 하나. "한국의
분리배출은 어렵지 않습니다"가 처음 만나는 문장이다. 겁부터 먹고 아무 봉투에나 넣는 것이 가장
흔한 일이라 그렇게 잡았다.

### 영상으로 배우기

2분짜리 안내 영상에 **네 언어 자막**이 붙는다. 자막은 브라우저가 WebVTT만 읽는데 만들어지는
쪽에서는 SRT로 오기도 해서, **실행 중에 변환**하도록 만들었다. 확장자가 아니라 내용을 보고
판정한다 — `.vtt`라는 이름으로 SRT가 들어온 적이 실제로 있었다.

### 도감

16종을 검색·분류로 찾고, 누르면 처리 순서와 흔한 실수, 공식 출처를 본다.

- 검색은 고른 언어와 **한국어를 항상 함께** 본다. 한국에서는 결국 한국어 단어를 마주치기 때문
- **사진으로 찾기**가 도감 안에 들어 있다. 사진을 올리면 Gemini가 품목을 짚어 도감으로 잇는다
- 사진을 올리기 **전에** 개인정보 고지문이 뜬다. 무료 등급에서는 제출 이미지가 학습에 쓰일 수
  있어서다. 늘 띄워 두면 읽지 않으므로 그 순간에만 보여 준다

### 게임

무엇을 하는 게임인지 한 번 안내한 뒤 시작한다. 품목이 가운데 뜨고 좌우에 수거함 넷이 있다.
틀리면 왜 틀렸는지 알려 주고, 끝나면 맞은 것과 틀린 것을 나눠 보여 준다.

### 챗봇

어느 화면에서든 우하단 단추로 연다. 화면을 옮겨도 대화가 남도록 라우트 바깥에 뒀다.

**근거를 세 등급으로 나눈다.** 도감이 다루는 것은 도감대로 답하고 출처를 붙인다. 도감 밖은 아는
대로 답하되 출처를 붙이지 않고 "도감에 없으니 지자체 확인이 필요하다"를 답변 안에 적는다.
분리배출과 무관한 질문에는 답하지 않는다. 모델이 등록되지 않은 출처를 붙여 와도 화면까지 가지
못하게 막아 뒀다.

### 네 화면 공통

- 언어 전환은 한 번에 화면 전체에 걸린다 (ko / en / zh / vi)
- 진행 막대가 넷 중 어디인지 보여 주고, 지금 페이지는 상단 메뉴에 초록 네모로 표시된다
- 기능마다 오류 경계를 둬서 하나가 죽어도 나머지 화면은 살아 있다
- 모달은 포커스를 가두고, 페이지를 옮기면 본문으로 포커스를 보낸다
